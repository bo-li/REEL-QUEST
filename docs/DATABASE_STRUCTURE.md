# Database Structure

## REEL-QUEST Schema Specification (schema v0.3, taxonomy v13)

This document describes the record structure of the REEL-QUEST ligand database,
`data/sx_ligands_merged_v14_flat.jsonl`.

## File Format

- **File**: `data/sx_ligands_merged_v14_flat.jsonl` (169 records, 1,833 experimental conditions)
- **Format**: Newline-delimited JSON (one ligand record per line)
- **Encoding**: UTF-8

> **Two version fields, two meanings.** `schema_version` (currently **`v0.3`**)
> describes the **record structure** — which fields exist. `metadata.taxonomy_version`
> (`v13_flat`) describes the **classification generation** — how ligands are grouped.
> They change independently; do not read one for the other.

## Machine-readable schema

- **`schema/ligand_record.schema.json`** — JSON Schema (draft 2020-12) for one record. Every enumeration (trend classes, mechanisms, the 21 subtypes, element symbols) is injected from the code, and every object is closed (`additionalProperties: false`), so an unknown or misspelt field fails validation.
- **`schema/data_dictionary.csv`** — one row per field: path, type, whether required, **units**, **provenance** (`source-transcribed`, `curated`, or `derived: <function>`), and a description.

Both files are generated by `scripts/generate_json_schema.py` and checked by `tests/test_json_schema.py`. `python scripts/validate_database.py` applies the schema, on top of the cross-field checks in `rel_quest/validators.py` that a schema cannot express (D vs log D, coverage vs measurements, a compilation DOI cited as a measurement). Every derived field reproduces from the stored measurements — `python scripts/recompute_derived_fields.py --check` (`rel_quest/derived.py`).

## Schema Overview

```json
{
  "schema_version": "v0.3",
  "ligand": {...},
  "selectivity": {...},
  "experimental_data": [{...}],
  "performance_summary": {...},
  "data_quality": {...},
  "metadata": {...},
  "elements_measured": [...]
}
```

## `ligand` (object)

| Field | Type | Description |
|-------|------|-------------|
| `Name` | string | Common ligand name; unique. The canonical SMILES, not `Name`, is the primary key |
| `SMILES` | string | Molecular structure; every record has one, all parse under RDKit, no two share a canonical form |
| `IUPAC_Name` | string \| null | Systematic name |
| `InChI` / `InChI_Key` | string | Standard InChI identifiers |
| `Molecular_Formula` / `Molecular_Weight` | string / number | RDKit-derived |
| `PubChem_CID` | string | PubChem compound ID where resolvable |
| `CAS_Number` | string | CAS registry number (sparse) |
| `Alternative_Names` | array | Genuine **synonyms only**: literature codes, typographic variants, and names superseded by renames |
| `Community_Name` | string | Nickname (not curated; use `Name` and `Subtype`) |
| `Subtype` | string | **Canonical classification.** One of 21 values — see `vocab/chemical_families.json` v2.1 |
| `Chemical_Family` | string | Holds the **same** value as `Subtype` (kept for consumers of the earlier two-layer taxonomy) |
| `Mechanism` | string | `Solvation` or `Cation_Exchange` |
| `Extractant_Type` | string | Legacy SMARTS-derived class, superseded by `Subtype` |

### Subtype vocabulary (21 values, grouped by donor chemistry)

**O-donor:** `DGA`, `Malonamide`, `Crown_ether`, `Tripodal-DGA`, `Amide`, `Polyether_Diamide`, `Phthalamic_acid`, `Butanediamide`, `Polyphenol`
**N,O-hybrid:** `DAPhen`, `Bipydiamide`, `Pyridinediamide`, `MAPhen`, `EDTA` (no record at present), `Nitrilotriacetamide`, `BLPhen`
**N-donor:** `Multident_N_donor`
**P-donor:** `Phosphine_oxide`, `Phosphonate`, `Phosphate`, `Phosphoric_acid`

The donor groups are documentation only — records carry the flat 21-label `Subtype` directly. Counts: `paper/stats.json` (`subtypes`).

## `selectivity` (object)

| Field | Type | Description |
|-------|------|-------------|
| `trend_classification` | string | See the 7-value vocabulary below |
| `trend_confidence` | string | `High` (unanimous), `Medium` (> 70 % agreement), `Low`, or `None` for `Insufficient_Data` |
| `element_coverage` | array | La–Lu elements the trend fit used (never Y/Sc; never a bound) |
| `slope` | number \| null | Mean of the per-condition slopes of log D on atomic number |
| `r_squared` | number \| null | Mean per-condition R² of that fit |
| `slope_CI_lower` / `slope_CI_upper` / `slope_std` | number \| null | 95 % bootstrap interval for `slope` from `rel_quest.uncertainty.bootstrap_trend_ci`: a two-stage bootstrap that resamples conditions, then points within each drawn condition, and averages the per-condition slopes — the same estimator `slope` is. Seeded, so the stored values reproduce |
| `peak_element` | string | Element at the extremum — present only for `Peaked` and `U_Shaped` |
| `notes` | string | How the trend was derived |

### Trend classification values

| Value | Meaning |
|-------|---------|
| `Ascending` | D increases La→Lu (heavy-REE preference) |
| `Reverse` | D decreases La→Lu (light-REE preference); displayed as "Descending" |
| `Flat` | No significant trend |
| `Peaked` | Maximum at a mid-series element |
| `U_Shaped` | Minimum at a mid-series element |
| `Mixed` | Conflicting trends across conditions |
| `Insufficient_Data` | Too few lanthanides measured in any condition to fit |

Per condition, a linear regression of log D on atomic number gives Ascending,
Reverse or Flat; a peak-position heuristic (≥ 4 elements, interior extremum,
≥ 0.3 dex on both sides) overrides it with Peaked or U_Shaped; votes are then
aggregated across conditions (`rel_quest.trends.classify_selectivity_trend`).
Consumers validating this field must accept all seven values — import
`rel_quest.schema.TREND_CLASSIFICATIONS`. Counts: `paper/stats.json`
(`trend_classes`).

## `experimental_data` (array of objects)

One object per experimental condition.

| Field | Type | Description |
|-------|------|-------------|
| `condition_id` | string | Unique, stable condition identifier (`RQ-000001`, …) |
| `Acid_Name` | string | Aqueous acid (typically HNO3; `Hcl` is hydrochloric acid as spelled in the source) |
| `Acid_Concentration_M` | number \| null | Initial aqueous acid concentration, mol L⁻¹ |
| `Temperature_C` | number | Temperature, °C |
| `Solvent_Name` | string | Organic diluent |
| `Solvent_Ratio` | string \| null | Volume ratio for mixed diluents, e.g. `7:3` |
| `Extractant_Concentration_M` | number \| null | Ligand concentration in the organic phase, mol L⁻¹ |
| `Phase_Modifier_Name` | string | Organic phase modifier (empty string if none) |
| `Phase_Modifier_Concentration_M` | number \| null | Modifier concentration, mol L⁻¹ |
| `Contact_Time` | string | Contact/equilibration time with unit |
| `Additives` | string | Other aqueous components, free text |
| `Co_Extractants` | array \| null | Other extractants in the organic phase (see below) |
| `distribution_ratios` | object | D-values per element |
| `statistics` | object | Per-condition summary |
| `reference` | object | The paper that measured the values |

**`Co_Extractants`** — `[{"Name", "SMILES", "Concentration_M"}]` for a
condition measured with a mixed solvent (e.g. CyMe4-BTBP + 0.005 M TODGA). The
D belongs to the mixture, not to the record's ligand alone, so the condition is
kept on the main ligand's record and shown in its condition table, but
`rel_quest.uncertainty.is_mixture` leaves it out of everything pooled across
conditions: the selectivity fit and its bootstrap, outlier checks,
`get_aggregated_d_values`, and the dashboard's single-element and logSF
viewers. Its elements still count in `elements_measured`.

**`distribution_ratios`** — keys are element symbols:

```json
{
  "La": {
    "value": 0.095,
    "log_value": -1.022,
    "n_replicates": 1,
    "sigma_log_D": 0.0715,
    "source_quality": "figure",
    "value_origin": "digitised"
  }
}
```

| Field | Description |
|-------|-------------|
| `value` / `log_value` | D and log₁₀ D; they agree within 0.01 dex |
| `censor` | `>` or `<` for a bound (D > x, D < x). A bound stays out of every fit, median, statistic and separation factor |
| `value_origin` | `reported` (printed in a table or text), `digitised` (read from a figure), `interpolated`, `derived`, or `censored` |
| `sigma_log_D` | Uncertainty of log D (1σ). Measured for this value when `sigma_source` is `measured` (e.g. from the figure's calibration); otherwise a prior by `source_quality`: 0.0715 dex for figure-read (the median reading uncertainty of the calibrated figures), 3.5 % relative (0.0152 dex) for tabulated |
| `source_quality` | `table` or `figure`: how the value was read |
| `n_replicates` | Number of source values behind this cell |

**`statistics`** — `mean_log_d`, `std_log_d`, `min_log_d`, `max_log_d`,
`n_elements` of the condition's own values (bounds excluded), written by
`rel_quest.utils.condition_statistics`.

**`reference`**:

| Field | Type | Description |
|-------|------|-------------|
| `DOI` | string \| null | Bare, lower-case DOI of the paper that **measured** the values (`^10\.\d{4,9}/[^\s,]+$`). Never a compilation's DOI |
| `URL` | string | Source link, present only when the paper has no DOI |
| `Locator` | string \| null | Where in that paper: `"Figure 3"`, `"Table S2"`, `"Text, p. 7"` |

## `performance_summary` (object)

A cache of counts: `conditions_tested`, `total_measurements` (number of
D-values) and `elements_tested` (same list as `elements_measured`), written by
`rel_quest.derived.performance_summary`.

## `data_quality` (object)

| Field | Type | Description |
|-------|------|-------------|
| `overall_quality_score` | number | Composite score (0–100) of the slope interval's width, element coverage, the share of tabulated values and outliers |
| `quality_grade` | string | `High` / `Medium` / `Low` |
| `outlier_flags` | array | Measurements off their own condition's linear trend. Each eligible condition (≥ 4 lanthanides) is fitted separately and the pooled residuals Z-scored; \|Z\| > 3 flags, > 4 is `High`. On a Peaked/U_Shaped condition a flag can reflect curvature rather than error |

## `metadata` (object)

| Field | Type | Description |
|-------|------|-------------|
| `added_date` | string | Date the record was added |
| `last_updated` | string | Date the record's content last changed |
| `taxonomy_version` | string | Classification generation (`v13_flat`) |

## `elements_measured` (array)

Every element with a measurement in any condition, including Y and Sc, in
periodic order. Filters that ask "was this element measured?" read this field;
`selectivity.element_coverage` lists only the La–Lu points the trend fit used.

## Conventions

- **DGA chain-length naming follows SAFE's convention**, not the most common literature one: TODGA = C8, TDDGA = C10, TDdDGA = C12. The SMILES is authoritative.
- **DOIs are normalised**: bare, lower-case, one per condition.
- **Floor values**: a few cells store log D = −4.0 exactly (D = 10⁻⁴), a detection floor rather than a measurement.

## Version history

- **v0.1** — ligand / selectivity / experimental_data / performance_summary / metadata.
- **v0.2** — the `data_quality` block; naming and classification fields on `ligand`; selectivity confidence intervals; `sigma_log_D` and `source_quality` on every cell.
- **v0.3** — `reference.DOI` a bare DOI of the measuring paper, with `URL` and `Locator`; bounds (`censor`), `value_origin`, `sigma_source` and `Co_Extractants`.
